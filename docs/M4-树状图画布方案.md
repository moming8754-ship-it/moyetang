## 〇、一句话方案

**自绘 SVG（只画连线）+ HTML 节点卡片 + overlay 三图标**，自动布局是**确定性两趟分层算法**；
所有树改动走**新增的 Rust `note_tree_*` 命令族**（读盘 → 改 → `store::atomic` 原子写），前端只管布局、命中测试和渲染。

## 一、为什么不用 dagre / React Flow

| 方案 | 判断 |
|---|---|
| 装 dagre / React Flow | ❌ 要 `npm install`。本机沙箱不给写 `%LOCALAPPDATA%\npm-cache`，M3 是绕到工作区缓存才装上的（`进度.md` 五）。且 React Flow 的核心价值（自由摆放节点、任意连线）**正好撞红线「认知区无限画布」** |
| 自写分层 | ✅ 左→右 tidy tree 就 60 行纯函数，天生支持折叠，零依赖，行为完全可控可测 |

约定里写的是「React Flow **或自绘 SVG**」——取后者，红线更安全。

## 二、数据模型改动（M4 唯一的结构改动）

`TreeNode` 现在没有"来源"字段，M4-6 的**来源标记**必须先补上。

```rust
// src-tauri/src/models.rs
pub struct TreeNode {
    pub id: String,
    pub text: String,
    pub asset_path: Option<String>,
    pub collapsed: bool,
    pub children: Vec<TreeNode>,
    /// 【新增】联动进来的信息 id（信息区 → 树节点，单向可见）
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub source_info_id: Option<String>,
}
```

- `#[serde(default)]` → **旧笔记文件照样能读**（守「加字段必须带 default」）
- `note.rs::link_info` 写节点时带上 `source_info_id: Some(info.id.clone())`（现在只写 text/assetPath）
- 前端 `types.ts` 的 `TreeNode` 加 `sourceInfoId?: string`（两端成对改）
- 单元测试：① 联动后节点带来源 id；② 手工去掉该字段的旧 json 能读出来

**不变**：`-[]` / `markerKey` / `sync_markers` 一律不动（树笔记不产待办，`sync_markers` 里对 `NoteKind::Tree` 的 early-return 保持原样）。

## 三、写入路径：`note_tree_*` 命令族（**这是本方案最关键的取舍**）

### 3.1 两个候选

| 方案 | 做法 | 问题 |
|---|---|---|
| A. 整篇覆盖 | 前端改内存树 → 复用 `note_save` 整篇写回（跟 M3 编辑器一样） | ⚠️ **有覆盖竞态**：树笔记可能被后端改（`link_info` 往里加节点）。若前端握着一份旧树保存，刚联动进来的节点会被抹掉 —— 撞用户最在意的「数据不能丢」 |
| **B. 操作式（选它）** | 每个动作一条命令，Rust **读盘拿最新** → 改一处 → 原子写回 | 多写点 Rust，但**零覆盖风险**，且能在 Rust 里写单元测试（含防环） |

### 3.2 命令清单（都返回整篇 `Note`）

```
note_tree_add_child   (noteId, parentId, text?)              → Note
note_tree_add_sibling (noteId, nodeId, text?)                → Note   // 根节点报错
note_tree_remove      (noteId, nodeId)                       → Note   // 含整枝；根节点报错
note_tree_move        (noteId, nodeId, targetId, position)    → Note   // position: child|before|after
note_tree_set_text    (noteId, nodeId, text)                 → Note
note_tree_set_collapsed(noteId, nodeId, collapsed)            → Note
note_tree_set_image   (noteId, nodeId, assetPath?)           → Note   // 传 null 就是去掉图
```

- **全部经 `store::note::save` → `atomic::atomic_write_json`** ✅ 「一切写文件都走 store::atomic」一个字不改
- 新增 `store/tree.rs`：纯函数（`find_path` / `add_child` / `add_sibling` / `remove_branch` / `move` / `set_text` / `set_collapsed` / `set_image` / `count_nodes`），命令只是「读 → 调纯函数 → 写」
- **防环**：`move` 时目标是自身或自身后代 → 返回错误（`"不能把节点放进它自己的分支里"`）
- **根保护**：`remove`/`add_sibling` 对根节点返回错误，前端同时把按钮置灰（双保险，不靠前端拦）
- 单元测试（目标 +12 项）：增删改查、整枝删除计数、防环、根保护、折叠落盘、图片设置/清除、旧文件兼容

### 3.3 广播策略

**沿用 `note_save` 那条已有例外**，不新增规则：树操作**不广播 `data-changed`**（免得每次点一下全量重拉四个文件），前端用返回的 `Note` 就地把 `notes` 列表更新掉（`updatedAt` 跟着走，列表排序与后端一致）。
→ 新增 `dataStore.applyTreeOp(noteId, op)`，内部逻辑与 `saveNote` 的就地更新完全同构。

## 四、布局算法（确定性 · O(n) · 纯函数）

`src/features/tree/layout.ts`，无 React、无副作用，可直接单测。

### 4.1 节点尺寸（**布局前就能算出来**，所以不会抖动）

```
measure(node):
  hasImg = !!node.assetPath
  weight = Σ(中文字 1 / 其它字符 0.55)，上限 22
  lines  = weight ≤ 7 ? 1 : weight ≤ 16 ? 2 : 3
  w      = weight ≤ 7 ? 132 : weight ≤ 16 ? 180 : 224
  h      = lines * 22 + 18 + (hasImg ? 66 : 0)      // 图片缩略图 58 + 间距
```

**固定三档宽度 + 最多三行**：换来「零测量、零重排抖动」，长文本 CSS 截断 + 悬停 title 看全文 + 双击看全。
（不用 `getBoundingClientRect` 二次回流：那会让每敲一个字整张图抖一下。）

### 4.2 三趟

```
GAP_X = 72   // 层间距
GAP_Y = 16   // 兄弟间距

Pass1 后序：height(n) = 折叠或无子 ? h(n)
                      : max(h(n), Σ height(可见子) + GAP_Y*(k-1))

Pass2 层对齐：layerW[d] = max(该层可见节点 w)
              layerX[0] = 0
              layerX[d] = layerX[d-1] + layerW[d-1] + GAP_X

Pass3 前序：y = top + (height(n) - h(n)) / 2            // 父节点在自己区间里居中
            子节点从 top + (height(n) - Σchildren) / 2 起依次排下去
```

- **折叠**：`collapsed=true` → 子树完全不参与 Pass1/2/3（折叠就是"看不见"，不用额外坐标逻辑）
- **层对齐**：同深度的节点左边缘 x 相同 → 层次分明，是「思维导图」而不是「随机树」
- 输出：`{ nodes: [{id, x, y, w, h, depth, hasChildren, collapsedCount}], edges: [{from, to}], bounds: {w, h} }`
- 坐标原点左上，已含 `PAD = 32` 内边距

### 4.3 连线

父右中点 → 子左中点，三次贝塞尔：

```
M px+pw, py+ph/2   C px+pw+GAP_X*0.5, py+ph/2
                     cx-GAP_X*0.5,     cy+ch/2
                     cx,               cy+ch/2
```

圆角柔顺曲线（小米笔记那种手感），`stroke-width 1.5`，主题色 `slate-300 / slate-700`。

## 五、画布结构 & 缩放平移

```
<div class="canvas">                         ← 剪裁 + 接滚轮/空白拖动
  <svg class="absolute inset-0 pointer-events-none">   ← 只画连线
  <div class="world" style="transform: translate(tx,ty) scale(k); transform-origin: 0 0">
      {节点卡片 × N}                        ← HTML div，absolute 定位
  </div>
  <div class="overlay absolute inset-0 pointer-events-none">
      {选中节点的三图标条}                   ← 固定尺寸，不随缩放变小
  </div>
</div>
```

**为什么节点用 HTML 而不是 SVG `<rect>`**：图片缩略图、行内 `<textarea>` 编辑、Tailwind 样式都是 HTML 的原生强项；而且 CDP 验收能直接
`document.querySelector('button[title="加子节点"]').click()` —— 可验证性差一个量级。

| 手势 | 行为 |
|---|---|
| 滚轮 | 缩放，锚点 = 鼠标位置：`k' = clamp(k·e^(-Δy·0.0015), 0.4, 2)`；`tx' = mx - (mx-tx)·(k'/k)`（ty 同理） |
| 空白处按住拖 | 平移（红线禁自由摆放节点，所以空白拖动不会和节点拖动打架） |
| 首次进入 / 切笔记 | 自动 fit：`k = clamp(min(视口/内容), 0.4, 1)` 后居中 |
| `⌖` 按钮 / `Ctrl+0` | 重置视图（回 1:1 并居中） |
| `−` / `+` 按钮 | 以视口中心为锚缩放 |

**保存不重置视口**（每次落盘都跳回原点会很烦）。

## 六、选中与三图标（用户明确指定的交互，**不加第四个**）

- 单击节点 = 选中；点空白 / `Esc` = 取消选中
- 选中后，节点**右上角外侧**浮一条三图标工具条（overlay 层，固定 28px）：

```
left = tx + (x + w) * k - 14
top  = ty + y * k - 14        // 会钻出画布顶部时翻到节点内侧下方
```

| 图标 | 行为 | 根节点上 |
|---|---|---|
| 🗑 | 删**当前节点 + 整个分支**。`askConfirm`（danger）写明「将删除 N 个节点（含子分支）」，二次确认 | **置灰**，title「中心主题不能删」 |
| ⊕ | 加**子节点**：追加到 children 末尾，`collapsed=false`，新节点立刻进入编辑态 | 可用 |
| ⋮＋ | 加**同级节点**：插到当前节点在其父 children 里的**后面**，立刻进入编辑态 | **置灰**，title「中心主题没有同级节点」 |

图标大小 / 顺序 / 含义严格照 `笔记App-页面结构与交互设计.md` §4.3 的表，**不自作主张换别的**。

## 七、编辑与键盘（「随手就能往下长」的关键）

分两态，规则不打架：

| 按键 | 节点被选中（非编辑态） | 节点编辑态 |
|---|---|---|
| `Enter` | 新建**同级** + 进入编辑 | **提交 + 新建同级 + 进入编辑** ← 敲完一条马上敲下一条 |
| `Tab` | 新建**子级** + 进入编辑 | **提交 + 新建子级 + 进入编辑** |
| `Shift+Enter` | — | 节点内换行（不退出） |
| `Esc` | 取消选中 | 提交并退出编辑（不新建） |
| `F2` / 双击 / 直接敲字 | 进入编辑，全选原文字 | — |
| `↑ ↓` | 前后一个**可见**节点（按布局 y 顺序） | — |
| `←` / `→` | 父节点 / 第一个子节点（折叠则先展开） | — |
| `Delete` | 删分支（走二次确认） | — |

- 编辑态节点内换成 `<textarea>`（autofocus + 全选），**失焦即提交**
- **不逐字保存**：文字只在提交那一刻写一次盘。所以树笔记**不需要防抖、不需要串行队列、不需要序号守卫**（M3 编辑器那一套是因为它边打字边存）
- 新节点默认文字 `新节点`

## 八、拖拽（调层级 / 顺序，**不是改坐标**）

用 pointer 事件自绘，不用 HTML5 DnD（在自定义画布上手感差、移动端不友好）。

| 落点 | 结果 |
|---|---|
| 落在节点**中间 60%** | 成为它的**最后一个子节点** |
| 落在节点**上 20%** | 成为它的**前一个同级** |
| 落在节点**下 20%** | 成为它的**后一个同级** |
| 落在空白 | 取消，回原位 |

- 拖动中：被拖子树半透明跟随；候选落点高亮（进 child 画环形描边，进 before/after 画一条粗插入线）
- **防环**：目标是自己或自己的后代 → 该节点画 `not-allowed` + toast「不能把节点放进它自己的分支里」（Rust 也拦一道）
- 拖拽移动的是**层级/顺序**，节点坐标始终由自动布局算出来 —— **红线安全**

## 九、节点插图片

- **入口**（三图标已经被用户锁定为三个，所以图片入口不占图标位）：
  1. 节点**编辑态**里出现「🖼 插图片」小按钮 → 走 Tauri 文件选择？❌ 没装 `tauri-plugin-dialog`（那是 M7 的插件）
  2. → 所以用：**把图片文件直接拖到节点卡片上**（节点高亮 + 显示「松手插到这张卡片」）
- 技术路径：`getCurrentWebview().onDragDropEvent` → `payload.type==='over'|'drop'` 带 **`position: PhysicalPosition`** → 除以 `window.devicePixelRatio`（本机 150% 缩放，不除必定错位）→ 命中测试找节点 → `asset_import(path)` 拿相对路径 → `note_tree_set_image`
- 节点内有图时：卡片底部显示 58px 高缩略图（`object-cover`），点击看大图
- 去掉图片：编辑态缩略图右上角一个小 `×` → `note_tree_set_image(assetPath: null)`（**只解除引用，不删 `assets/` 里的原文件** —— 遵守「删除留后路」）
- ⚠️ 两个页面都会挂 `onDragDropEvent`，但 `App.tsx` 一次只渲染一个页面（`const Page = PAGES[view]`），切走就卸载 → **不会双收**。这一点在实现时再核一遍

**看大图**：从 `InfoPage.tsx` 抽出公共组件 `components/ImageViewer.tsx`（按窗口宽度铺满 + 容器可滚动 + `原图 1:1 / 适应宽度` 切换 + 点背景/Esc 关闭），InfoPage 改为用它。
→ 顺手消掉重复代码，更重要的是**保证不重复踩 M3.1 那个「`max-h-full` 把手机长图压成窄缝」的坑**。代价是动了 M3 已验证的页面 → 验收里**回归「点击看大图」那条**。

## 十、联动信息的来源标记（M4-6）

- 节点带 `sourceInfoId` 时：卡片**左边线**（`border-l-2 border-indigo-400`）+ 浅底色 + 左上角 `〔联动信息〕` 小徽标 —— 与 M3 文本笔记的引用块**同一套视觉语言**
- 徽标**可点** → `setFocusRef({kind:'info', id})` + `setView('info')` → 跳回信息区并高亮 2.8 秒（M3 已打通的通道，直接复用）
- 不做斜体：节点文字斜体不好读，且节点本身就短
- 联动进来的节点**就是个普通节点**：可以改文字、加子节点、拖动、删除
- 保证「单向可见」：树节点只记 `sourceInfoId`（一个 id），信息区只显示「→ 认知区《XX》」快照，**读不到节点文字**

### 验收逼出来的两条真 bug（都是"数据会悄悄丢"）

1. **树笔记标题只在 `onBlur` 里保存** → WebView 里程序化 `blur()` 不一定触发 React `onBlur` → 改了标题点走，标题变回原名。
   `DocNotePane` 没这毛病，是因为它有 900ms 防抖兜底。**改成"防抖 + Enter 提交 + onBlur 兜底"多路保底。**
2. **节点文字同理** → 双击写完直接点走会丢字。**加了编辑态防抖自动保存（只存字、不退出编辑）。**

修第 1 条时还顺手踩了一个 React 坑：`useEffect(() => () => void commitTitle(), [commitTitle])` ——
`commitTitle` 的依赖里有 `title`，**每敲一个字它就换身份，于是这个 effect 的 cleanup 每次都跑**，
用旧闭包把"脏"标记清掉并早退，防抖计时器也跟着不排了。
**unmount-only 的 effect 依赖必须是 `[]`**，要调的函数放 ref。

## 十六、M4.1 · 真实试用反馈修复（2026-09-20）

用户拿着 M4 画了一张真图（「密码学联系」，12 个节点），提了 4 条，全部修完并验证。
**方案文档里"合成事件验收"这个做法本身被证明不够**，这条教训比任何一条 bug 都值钱。

### 最关键的一条：整套脚本全绿，功能对用户却完全不可用

**症状**：所有节点（含中心主题）双击都进不了编辑态。

**根因**：`pointerdown` 里立刻 `setPointerCapture` → 指针被画布容器捕获 → 浏览器把随后的
`pointerup` 也投递给容器 → `click`/`dblclick` 的目标按"按下与松开目标的最近公共祖先"算 →
**变成画布容器** → 节点卡片上的 `onDoubleClick` 永远不触发。

**为什么脚本没抓到**：脚本用 `dispatchEvent(new MouseEvent('dblclick'))` **直接派发到节点元素**，
绕过了命中测试、指针捕获与焦点处理 → 假绿灯。

**修法**：推迟到真的越过拖拽阈值（5px）才捕获；容器上再加一道按坐标命中的 `onDoubleClick` 兜底。

**流程修法（更重要）**：`cdp.ps1` 增加 `-Action mouse`（走 CDP `Input.dispatchMouseEvent`，
真实单击/双击/拖拽），新增 `tools/m4/realgesture.ps1`。
**以后手势类交互（双击/拖拽/长按）一律用真实输入验一遍，不许只信 `dispatchEvent`。**

### 同一类"合成测不出"的另外两条（真实输入才暴露）

1. **`pointerdown` 落在 `<img>` 上会触发浏览器原生图片拖拽** → 页面再也收不到
   `pointermove`/`pointerup` → **带图片的节点完全拖不动**。
   修法：画布内一律 `draggable={false}` + 容器 `onDragStart` 阻止默认。
2. **快速拖拽的落点判断会丢**：`endPointer` 读 state（`dropHint`），真实拖拽的 mouseup 紧跟着
   mousemove、React 还没重渲染 → 闭包里是旧值 → 拖拽白做。
   修法：**事件里只读 ref**，state 留给渲染。

### 另外三条反馈

| 反馈 | 根因 | 修法 |
|---|---|---|
| 标题里的「未命名笔记」全删掉又被自动补回来，没法改标题 | 防抖 900ms 到点落盘，空标题被后端兜底成「未命名笔记」再塞回输入框，把正在打的字搅乱 | **空值不参与防抖保存**（只在 Enter/失焦这种"明确结束编辑"时才落盘）；**只在明确结束编辑时才把兜底值写回界面** |
